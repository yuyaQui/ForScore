# 準決勝: 3セット制タイムレース Nine Hundred 設計メモ

9名 → 3名。ルールの出典は `abc the24th ルール` の「準決勝」節。

このメモは実装前の設計合意を目的とする。

---

## 1. ルール概要

- 9名が3セットの早押しクイズを「タイムレース形式」（矢継ぎ早に出題、フォローはセット後にまとめて）で行う。
- ポイントは正解・誤答で増減し、**セットをまたいでリセットされない**（持ち越し）。
- セットごとのポイント配分:

  | | 参加者数 | 正解 | 誤答 |
  |---|---|---|---|
  | 第1セット | 9人 | +1 | -1 |
  | 第2セット | 6人 | +1 | -2 |
  | 第3セット | 3人 | +2 | -2 |

- **各セット終了時点**でポイント上位1名が勝ち抜け、下位2名が失格。これを3セット繰り返すことで9人→3人になる（各セットで3人ずつ抜ける：勝ち抜け1 + 失格2）。
- 出題時間は各セット5分間（3セット合計15分）。5分に達した瞬間に読み始めていた問題は、正解・誤答・スルーが決まるまで有効。
- **境界に同点が並んだ場合**（勝ち抜けの1名を決めきれない、または失格の2名を決めきれない）、該当者のみで早押しプレーオフ（1問正解で勝ち・1問誤答で負け）を行う。プレーオフの正解・誤答は**それまでのポイントに影響しない**（勝ち抜け/失格の決定にのみ使う）。

## 2. 3rd Round から流用できるもの

3rd Round の10 up-downと近い部分が多い。

| 3rd Round の部品 | 準決勝で使えるか |
|---|---|
| 純関数に採点を切り出す構造 | そのまま使う |
| スナップショット方式の Undo | そのまま使う |
| 15分タイマー（コースごとの残り秒数） | 同じ仕組み。セットごとの残り秒数として使う |
| 早押しプレーオフ（`applyPlayoffScore`） | そのまま使う |
| 判定基準・同値判定（`compareByCourseCriteria` / タイ検出） | 考え方は使うが、**境界が2箇所になる**分の拡張が要る（3章） |
| 順位フィールドの規約（勝抜→正、失格→−1、未決着→0） | そのまま使う。正の数は「何セット目に勝ち抜けたか」を表せる（4章） |

## 3. 3rd Round にない新しい複雑さ

### 3.1 境界が2箇所ある

3rd Round は「勝ち抜け境界」の同点だけを見ればよかった（失格は誤答2回の累積で決まり、終了時のランキングに左右されないため）。

準決勝は**勝ち抜け（上位1名）と失格（下位2名）の両方が、セット終了時点のランキングで決まる**。したがって、

- 1位と2位が同点 → 勝ち抜け側のプレーオフ
- 残り枠の最後（安全圏の最下位）と失格圏の最上位が同点 → 失格側のプレーオフ

の両方を判定する必要がある。3rd Round の `finalizeCourseByStandings` を土台にしつつ、境界判定を2箇所に増やす拡張が要る。

### 3.2 セット間でポイントを引き継ぐ

3rd Round はコースが変われば別人（コースごとに5名固定）だったが、準決勝は**同じ6名・3名がセットをまたいで生き残り、ポイントも持ち越す**。「アクティブな人だけが次のセットに進む」という他は、2nd Round の組やり直しとも3rd Roundのコースとも違う形。

### 3.3 準決勝の勝ち抜け順が決勝の判定基準に使われる

決勝（トリプルセブン）の順位判定基準の最後に「準決勝での勝ち抜けが早い順」がある。つまり、**準決勝で何セット目に勝ち抜けたか**を記録しておく必要がある。

`semifinalRank` を「勝ち抜け→正の数、失格→−1、未決着→0」の規約のまま使い、正の数を **勝ち抜けたセット番号（1〜3）** にすればこれをそのまま満たせる（1セット目勝ち抜けが最速）。

### 3.4 参加者と席の決め方

準決勝の9名は、既存データから導出できる。

- 3rd Round 通過8名（`thirdRoundRank` 1〜8） → 設計メモ `3rd-round-design.md` 5.2 の `SEMIFINAL_SEATS = [4, 6, 3, 7, 2, 8, 1, 9]` で1〜8番席のうち8席に着席（5番席だけ空く）
- Extra Round 敗者復活者（`extraRoundRank === 1`） → 5番席

**新しい列は不要**。席番号は `thirdRoundRank` と `extraRoundRank` から都度導出できる。

## 4. 決定事項

### 4.1 スキーマ追加（Player）

```prisma
// 準決勝
semifinalPoint Int @default(0) // セットをまたいで持ち越す累計ポイント
semifinalRank  Int @default(0) // 勝ち抜け→勝ち抜けたセット番号(1〜3)、失格→−1、未決着→0
```

**正解数・誤答数は列として持たない。** ルール上の判定にも使わず、Main にも出さないため（4.2）。DB はポイントだけで足りる。

### 4.2 Main は「クイズ中」と「点数発表」で画面を分ける

準決勝は「タイムレース形式」で、ルール上**セット中は司会のフォローも観客の反応もなく進行し、セット終了後にまとめて結果を確認する**。この進行に合わせて、Main の表示を2つに分ける。

| 画面 | 表示内容 |
|---|---|
| クイズ中 | 正解数・誤答数・ポイントは一切出さない（進行中であることが分かる程度） |
| 点数発表 | セット終了後、ポイントのみを表示する（正解数・誤答数は出さない） |

2nd Round の `view: 'turnOver' \| 'quiz'` と同様、進行状態に `view` を持たせて Admin から切り替える想定。Admin 自身は採点のためにポイントをリアルタイムで見る必要があるので、Admin 側の表示は隠さない。

### 4.3 プレーオフは 3rd Round と同じ `phase` で切り替える

進行状態に `phase: "quiz" | "playoff"` を持ち、境界に同点が出たら Admin の判断で `playoff` に切り替えて専用画面に遷移する（3rd Round と同じ形）。

## 5. 未決事項（相談したいこと）

1. **セット終了操作のタイミング。**
   3rd Round は「タイマーが0になったら『コース終了』ボタンが出る」形だった。準決勝も同じでよいか。同点判定（プレーオフが必要か）はこのタイミングで自動判定し、必要なら `phase: "playoff"` に遷移する想定。
2. **進行状態の置き場所。**
   `server/SemifinalHandler.js`（新規）に持たせる想定。中身は最小限で足りそうだが、想定は以下の通りでよいか確認したい。

   ```js
   let semifinalState = {
       set: 1,             // 1〜3
       phase: "quiz",       // "quiz" | "playoff"
       view: "quiz",         // "quiz" | "results"（Main の表示切り替え）
       finishedSet: null    // セット終了処理を走らせたセット番号
   };
   ```

3. **タイマーの持ち方。**
   3rd Round の `ThirdRoundTimer`（コースごとの残り秒数）と同じ形で、セットごとの残り秒数を持てばよいか。
