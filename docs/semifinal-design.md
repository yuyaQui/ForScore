# 準決勝: 3セット制タイムレース Nine Hundred 設計メモ

9名 → 3名。ルールの出典は `abc the24th ルール` の「準決勝」節。

このメモは実装前の設計合意を目的とする。

---

## 1. ルール概要

- 9名が3セットの早押しクイズを「タイムレース形式」（矢継ぎ早に出題、フォローはセット後にまとめて）で行う。
- ポイントは正解・誤答で増減し、**セットをまたいでリセットされない**（持ち越し）。
- セットごとのポイント配分:

  | | 参加者数 | 正解 | 誤答 |
  |---|---|---|---|
  | 第1セット | 9人 | +1 | -1 |
  | 第2セット | 6人 | +1 | -2 |
  | 第3セット | 3人 | +2 | -2 |

- **各セット終了時点**でポイント上位1名が勝ち抜け、下位2名が失格。これを3セット繰り返すことで9人→3人になる（各セットで3人ずつ抜ける：勝ち抜け1 + 失格2）。
- 出題時間は各セット5分間（3セット合計15分）。5分に達した瞬間に読み始めていた問題は、正解・誤答・スルーが決まるまで有効。
- **境界に同点が並んだ場合**（勝ち抜けの1名を決めきれない、または失格の2名を決めきれない）、該当者のみで早押しプレーオフ（1問正解で勝ち・1問誤答で負け）を行う。プレーオフの正解・誤答は**それまでのポイントに影響しない**（勝ち抜け/失格の決定にのみ使う）。

## 2. 3rd Round から流用できるもの

3rd Round の10 up-downと近い部分が多い。

| 3rd Round の部品 | 準決勝で使えるか |
|---|---|
| 純関数に採点を切り出す構造 | そのまま使う |
| スナップショット方式の Undo | そのまま使う |
| 15分タイマー（コースごとの残り秒数） | 同じ仕組み。セットごとの残り秒数として使う |
| 早押しプレーオフ（`applyPlayoffScore`） | そのまま使う |
| 判定基準・同値判定（`compareByCourseCriteria` / タイ検出） | 考え方は使うが、**境界が2箇所になる**分の拡張が要る（3章） |
| 順位フィールドの規約（勝抜→正、失格→−1、未決着→0） | そのまま使う。正の数は「何セット目に勝ち抜けたか」を表せる（4章） |

## 3. 3rd Round にない新しい複雑さ

### 3.1 境界が2箇所ある

3rd Round は「勝ち抜け境界」の同点だけを見ればよかった（失格は誤答2回の累積で決まり、終了時のランキングに左右されないため）。

準決勝は**勝ち抜け（上位1名）と失格（下位2名）の両方が、セット終了時点のランキングで決まる**。したがって、

- 1位と2位が同点 → 勝ち抜け側のプレーオフ
- 残り枠の最後（安全圏の最下位）と失格圏の最上位が同点 → 失格側のプレーオフ

の両方を判定する必要がある。3rd Round の `finalizeCourseByStandings` を土台にしつつ、境界判定を2箇所に増やす拡張が要る。

### 3.2 セット間でポイントを引き継ぐ

3rd Round はコースが変われば別人（コースごとに5名固定）だったが、準決勝は**同じ6名・3名がセットをまたいで生き残り、ポイントも持ち越す**。「アクティブな人だけが次のセットに進む」という他は、2nd Round の組やり直しとも3rd Roundのコースとも違う形。

### 3.3 準決勝の勝ち抜け順が決勝の判定基準に使われる

決勝（トリプルセブン）の順位判定基準の最後に「準決勝での勝ち抜けが早い順」がある。つまり、**準決勝で何セット目に勝ち抜けたか**を記録しておく必要がある。

`semifinalRank` を「勝ち抜け→正の数、失格→−1、未決着→0」の規約のまま使い、正の数を **勝ち抜けたセット番号（1〜3）** にすればこれをそのまま満たせる（1セット目勝ち抜けが最速）。

### 3.4 参加者と席の決め方

準決勝の9名は、既存データから導出できる。

- 3rd Round 通過8名（`thirdRoundRank` 1〜8） → 設計メモ `3rd-round-design.md` 5.2 の `SEMIFINAL_SEATS = [4, 6, 3, 7, 2, 8, 1, 9]` で1〜8番席のうち8席に着席（5番席だけ空く）
- Extra Round 敗者復活者（`extraRoundRank === 1`） → 5番席

**新しい列は不要**。席番号は `thirdRoundRank` と `extraRoundRank` から都度導出できる。

## 4. 決定事項

### 4.1 スキーマ追加（Player）

```prisma
// 準決勝
semifinalPoint Int @default(0) // セットをまたいで持ち越す累計ポイント
semifinalRank  Int @default(0) // 勝ち抜け→勝ち抜けたセット番号(1〜3)、失格→−1、未決着→0
```

**正解数・誤答数は列として持たない。** ルール上の判定にも使わず、Main にも出さないため（4.2）。DB はポイントだけで足りる。

### 4.2 Main は「クイズ中」と「点数発表」で画面を分ける

準決勝は「タイムレース形式」で、ルール上**セット中は司会のフォローも観客の反応もなく進行し、セット終了後にまとめて結果を確認する**。この進行に合わせて、Main の表示を2つに分ける。

| 画面 | 表示内容 |
|---|---|
| クイズ中 | 正解数・誤答数・ポイントは一切出さない（進行中であることが分かる程度） |
| 点数発表 | セット終了後、ポイントのみを表示する（正解数・誤答数は出さない） |

2nd Round の `view: 'turnOver' \| 'quiz'` と同様、進行状態に `view` を持たせて Admin から切り替える想定。Admin 自身は採点のためにポイントをリアルタイムで見る必要があるので、Admin 側の表示は隠さない。

### 4.3 プレーオフは 3rd Round と同じ `phase` で切り替える

進行状態に `phase: "quiz" | "playoff"` を持ち、境界に同点が出たら Admin の判断で `playoff` に切り替えて専用画面に遷移する（3rd Round と同じ形）。

## 6. 決定事項（2026-10-10、ユーザー回答）— 4.2・5章より優先

### 6.1 得点はセット終了後に、各選手のそのセットでの得点を入力する

1問ごとの正誤は記録しない（タイムレースの速さに Admin 操作を合わせない）。セット終了後、スタッフが手動で集計した「各選手のそのセットでの得点」を Admin で入力し、累計 `semifinalPoint` に加算する（土台の `applySemifinalSetPoints` の方式を維持）。

### 6.2 セット終了後の流れ

1. **問題の振り返り（Main）**: スタッフが得点を手動集計している間、そのセットで出題した問題と解答を Main に表示して振り返る
2. **得点入力（Admin）**: 振り返りと集計が終わったら、各選手のそのセットの得点を入力する
3. **点数発表アニメーション（Main）**: 各選手のポイントバーが「そのセットまでの合計得点」に向かって上昇する。最も点数が高い選手が決まったら、その選手のバーだけ上昇速度が上がり、最終的な高さは**それまでのラウンドで勝ち抜けたときと同じ高さ**になる
4. **判定（Admin・手動）**: アニメーション終了後にスタッフが勝ち抜け・敗退を判定する。境界に同点があればプレーオフ画面へ遷移する
5. **表示の切り替え（Main）**: 判定が終わったら、勝ち抜け選手・敗退選手の表示に切り替える

### 6.3 点数発表の見せ方

6.2 の流れに準拠する（2nd Round の Turn Over のような順位ごとの段階発表は行わない）。4.2 の「クイズ中はポイントを出さない」は維持する。

### 6.4 実装（2026-10-10）

| 役割 | 場所 |
|---|---|
| 判定（勝ち抜け→失格、同点ならプレーオフ）・得点入力の検証・「判定」1回で確定できる手順 | `lib/semifinalScoring.ts`（`getAdvanceJudgement` / `getEliminationJudgement` / `planSemifinalJudgement` / `getSemifinalSetStage`） |
| プレーオフの進行（押された操作の列から結果を計算） | `lib/semifinalPlayoff.ts` |
| 点数発表のバーの動き（Main の演出と Admin の待ち時間で共用） | `lib/semifinalAnnounce.ts` |
| 進行状態（表示段階・振り返り範囲とページ・得点入力済み・発表回数・プレーオフ） | `server/SemifinalHandler.js`（メモリ。項目ごとに検証） |
| 得点入力・判定の API | `app/api/semifinal/updateScore/route.ts`（`points` / `judgeAdvance` / `judgeEliminate`） |
| 画面 | `app/components/Admin/AdminSemifinal.tsx`・`AdminSemifinalParts.tsx`、`app/components/Main/MainSemifinal.tsx` |

決めた細部:

- **失格の同点**: 境界の点数に並ぶ全員でプレーオフを行い、残りの失格枠の人数を決める。境界より下の選手はプレーオフをせずに失格。プレーオフは「誤答で失格・正解で残留」、失格枠が埋まれば残り全員が残留、残りの人数が残りの枠と同じになれば残り全員が失格
- **勝ち抜けの同点**: 「正解で勝ち抜け・誤答で敗退（プレーオフから外れるだけ）」。残りが1名になればその選手が勝ち抜け
- **API は「どのセットのどの段階か」を DB から確かめてから受け付ける**（古い画面・二重送信で別の段階を書き換えない。合わなければ 409）。得点入力は対象全員ぶんを整数で求める
- 得点入力は全員0点でも Undo 用の履歴を残す（残さないと、入力直後の Undo が前のセットの判定を戻してしまう）
- **点数発表**: 最高得点者以外のバーは最大 75%。最高得点者だけ加速して 100%（勝ち抜けの高さ）。0点以下は空。カードの開扉（約2秒）が終わってから動き始める。Main は「開いている間に発表の回数が増えた」ときだけ演出し、リロード・途中から開いた場合は最終状態を出す。Admin の「判定 ▶」は演出が終わるまで押せない
- 「点数発表 ▶」は振り返り中かつ得点入力済みのときだけ受け付ける（二重送信で演出が2回流れない）。1本道ボタンは 800ms の連打防止つき（Extra Round と同じ）
- サーバ再起動でセット番号が 1 に戻っても、Admin は DB から進めるべきセットを求めて「第Nセットへ ▶」を出す
- 振り返りの問題は通し番号で指定し、`GET /api/questions?from&to`（Main は `&public=1` で別解を除く）で取得する。問題群の取り込み方法は未決のため、いまは検証用 `test_questions.csv`（90問）を読む（`lib/questionPool.ts`）
- Main の見た目は既存の部品（`PlayerCardFrame`・`FixedStage`、ヘッダー 40/50）で組んだ仮のもの。Design アーティファクトでの作り込みはこの後

## 7. 進出者紹介・新しい選手カード（2026-10-15、ユーザー決定・実装）

### 7.1 流れ

準備（standby）→ 進出者紹介（intro）→ 選手カード表示（lineup）→ 第1セットのクイズ画面（quiz）→ 6章の流れ。第3セットの判定後は Admin の「Final へ ▶」でモードを決勝に切り替える。

| Main 表示 | 内容 | Admin の1本道ボタン |
|---|---|---|
| `standby` 準備中 | 「準備中」の表示だけ | 写真・二つ名を登録 →「進出者紹介へ ▶」 |
| `intro` 進出者紹介 | 1人ずつ ①二つ名 → ②写真・学校名・学年・名前。奇数番目は写真が左、偶数番目は右。写真の枠は縦の軸で回りながら現れる | 「写真・プロフィールを表示 ▶」→「N人目へ ▶」→ 最後は「選手カードを表示 ▶」。「◀ 戻る」で1段階戻る |
| `lineup` 選手カード表示 | 紹介順に1枚ずつ（2nd〜Extra Round と同じ開扉）、最後に敗者復活者 | 演出が終わるまで「表示中…」→「第1セット クイズ画面へ ▶」。「◀ 戻る」で紹介の最後へ |
| `quiz` クイズ中 | 文字が消えてカードが写真だけを囲む大きさに縮み、下に長方形のタイマー | 6章と同じ |

- 紹介順は 3rd Round の実施コース順 → コース内 1位 → 2位（`getIntroOrder`）。敗者復活者は紹介しない（二つ名なし・写真はあり）
- 二つ名が未登録の選手は二つ名の画面を飛ばす。写真が未登録なら NO PHOTO を出す（未登録でも進行できる）
- 呼び名は「サドンデス」に統一（コード上の名前は `playoff` のまま）。Main の見出しは「勝ち抜けサドンデス」「失格サドンデス」
- 見出しは「Semifinal / Nine Hundred」（準備中は副題なし）

### 7.2 データ（DB）

| 項目 | 場所 | 内容 |
|---|---|---|
| 二つ名 | `Player.nickname`（`String @default("")`） | 12文字まで（絵文字なども1文字）。紹介する8名だけ登録できる |
| 写真 | 新しい表 `PlayerPhoto`（`playerId` 主キー・`mimeType`・`data Bytes`・`updatedAt`。選手を消すと一緒に消える） | 準決勝の9名（敗者復活者を含む）。Admin で 3:4 の範囲を手で切り抜き、600×800 の JPEG にして送る（2MB まで） |

マイグレーション: `prisma/migrations/20261015120000_add_semifinal_profile`。

**データの扱い（ユーザー方針）**: 大会で入力した情報（学校名・学年・名前・顔写真）は、その大会で使ったら全て削除する。写真は `Player` を消すと一緒に消える（`onDelete: Cascade`）。

### 7.3 API・Socket

| 種類 | 名前 | 内容 |
|---|---|---|
| API | `GET /api/semifinal/profiles` | 9名の `{ playerId, nickname, photoVersion }`（写真は版番号だけ） |
| API | `POST /api/semifinal/profiles` | `{ playerId, nickname }`。紹介する8名だけ。空文字で未登録に戻す |
| API | `GET /api/semifinal/photo?playerId=` | 写真の画像そのもの。URL に `&v=版番号` を付けて、差し替えたら必ず取り直す |
| API | `POST /api/semifinal/photo` | `{ playerId, dataUrl }`（JPEG / PNG / WebP） |
| Socket | `semifinal_profiles_changed` → `update_semifinal_profiles` | 保存したら Admin が送り、各画面が一覧を取り直す（中身は送らない） |
| Socket | `start_semifinal_lineup` | 選手カード表示を始める（`lineupSeq` を増やす。Main はこれが増えたときだけ演出する） |
| Socket | `request_semifinal_sync` | 画面を開いた時点で進行状態とタイマーを取り直す |

`SemifinalState` に `introIndex`（紹介順の何番目か）・`introStep`（`nickname` / `profile`）・`lineupSeq` を追加。表示の段階に `standby` / `intro` / `lineup` を追加し、初期値を `standby` にした。

### 7.4 選手カード

- `app/components/Main/SemifinalCard.tsx`。枠は 2nd〜Extra Round と同じ。中身は 写真（3:4）→ 1st Round 順位 → 学校名 → 学年 → 名前（姓・名を2行、名は1文字ぶん右にずらす）。行の高さは固定
- クイズ中は写真だけを囲む大きさに縮み、勝ち抜けたセット（1st / 2nd / 3rd）または LOST を写真に重ねる。縮むときは文字が先に消え、伸びるときは枠が先
- タイマー（`SemifinalTimerGauge`）は数字だけを中央に置き、枠線そのものが残り時間のゲージ（上中央から時計回り）。残り1分以下で赤
- カード表示の演出の時間（1枚 0.8 秒間隔・最後の前に 0.6 秒・1枚の登場 2.5 秒）は `lib/semifinalProfile.ts` に置き、Main の演出と Admin の「表示中…」の解除で共用する

## 8. セットの操作フローと結果リセット（2026-10-17、ユーザー指示・承認済み）— 6.2 より優先

### 8.1 1セットの流れ（Admin の1本道ボタン）

| # | 段階（view） | Main | Admin の1本道ボタン |
|---|---|---|---|
| ① | クイズ・開始前（quiz） | 縮んだカード＋タイマー 5:00 | 「タイマー START ▶」（途中で止めたときは「タイマー再開 ▶」） |
| ② | クイズ・計測中（quiz） | 同上 | 「計測中...」 |
| ③ | タイムアップ（quiz、残り 0） | 同上（00:00） | 本文に振り返る問題の通し番号の入力欄 →「問題振り返りへ ▶」 |
| ④ | 振り返り（review） | 1画面3問 | 「次の3問 ▶」→ 最後のページで「得点集計へ ▶」 |
| ⑤ | 得点集計（tally、新設） | 元の大きさのカード。決着済みの選手は WIN / LOST、他は得点欄が空 | 得点を入力 →「得点を確定 ▶」→「点数発表へ ▶」。確定前は「◀ 振り返りに戻る」 |
| ⑥ | 点数発表（results） | 同じカードのままバーが上がる（開扉演出はしない） | 演出が終わるまで「発表中...」→「勝ち抜け判定 ▶」 |
| ⑦ | 勝ち抜け判定 | 勝者が WIN。同点なら勝ち抜けサドンデス（playoff） | サドンデス後は「結果を確定 ▶」→「敗退判定 ▶」 |
| ⑧ | 敗退判定 | 敗退者が LOST。同点なら失格サドンデス | サドンデス後は「結果を確定 ▶」→「第N+1セット クイズ画面へ ▶」 |
| ⑨ | 次のセット | カードが縮んでタイマー 5:00 | ①へ。第3セットの後は「Final へ ▶」 |

- 判定は勝ち抜け・敗退を別のボタンで1つずつ確定する（`planSemifinalJudgement` の手順のうち、その目的のものだけを送る）
- 点数発表（`announce_semifinal_results`）は得点集計（tally）で得点を確定した後だけ受け付ける。発表前の間は 0.8 秒（`ANNOUNCE_START_DELAY_MS`。以前はカードの開扉を待つため 2 秒）
- 手動操作の「得点を入力し直す」は、直前の得点の確定を Undo で取り消してから得点集計に戻す（以前は「入力済み」の印を外すだけで、入れ直すと二重に加算されるおそれがあった）
- タイムアップ前に打ち切るときは、手動操作のタイマー EDIT で 0:00 にする

### 8.2 結果リセット
