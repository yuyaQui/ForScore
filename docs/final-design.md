# 決勝: トリプルセブン 設計メモ

3名 → 優勝者1名（+準優勝・第3位）。ルールの出典は `abc the24th ルール` の「決勝」節。

このメモは実装前の設計合意を目的とする。

---

## 1. ルール概要

- 準決勝を勝ち抜けた3名で、**3セット先取**の早押しクイズを行う。
- 各セットは独立している。**ポイント（正解数・誤答数）はセットごとにリセットされる**（準決勝と違い持ち越さない）。
- 各セットの決着条件は2つ。
  - 7問正解 → そのセットを獲得
  - 3回誤答 → そのセットにおいて失格（そのセット限りの失格。トーナメントから外れるわけではない）
- **2名が同じセットで失格した場合、残る1名が自動的にそのセットを獲得する**（Extra Round Second Step の「残り1名で自動敗者復活」、3rd Round の「残り人数＝残り枠」と同じ考え方）。
- 各セット終了時に20秒のインターバルタイムがあり、参加者はセコンド（各自2名まで）と作戦を練る。
- **3セットを先取した者が優勝**。セット数の理論上の上限は7セット。
- 優勝者以外の最終順位（準優勝・第3位）の判定基準:
  1. 獲得セット数が多い順
  2. 最終セットでの正解数が多い順（そのセットで失格した者の正解数も含む）
  3. 準決勝での勝ち抜けが早い順
  スタッフが手法で判定するため、具体的にシステムで実装する必要はない。
- 決勝に時間制限の記載はない（3rd Round の15分・準決勝の5分×3セットと違い、タイマーなしで進行する想定）。

## 2. 既存パターンから流用できるもの

| 部品 | 流用元 | 備考 |
|---|---|---|
| 早押しの正解/誤答ボタンの型 | 3rd Round・準決勝 | 対象1名への `correct`/`wrong` |
| 「残り1名で自動決着」 | Extra Round `finalizeLastActivePlayer` / 3rd Round `seatsMatchRemaining` | 2名失格→残り1名がセット獲得、に流用 |
| スナップショット方式のUndo | 全ラウンド共通 | そのまま使う |
| 順位フィールドの規約（勝抜→正の数、失格→−1、未決着→0） | 全ラウンド共通 | 決勝の最終順位（1〜3位）に使う。ただし「セット内失格」は別概念（3章） |
| `semifinalRank` を使った最終タイブレーク | 準決勝で「勝ち抜けたセット番号」として実装済み | 判定基準(3)にそのまま使える |

## 3. 既存ラウンドにない新しい複雑さ

### 3.1 「セット内失格」とトーナメント全体の状態は別物

3rd Round・準決勝の `-1` は「そのラウンドから外れた（もう解答席にいない）」を意味したが、決勝の「セット内失格」は**そのセットだけの一時的な状態**で、次のセットでは全員がまた解答権を持つ。したがって、

- セットごとの正解数・誤答数（リセットされる値）
- トーナメント全体での獲得セット数（累積、リセットされない）
- 最終順位（トーナメントが終わったときだけ確定する1〜3位）

の3種類を混同しないように設計する必要がある。

### 3.2 最終順位のタイブレークは行わない

優勝者は「3セット先取」で自明に決まるが、残り2名の順位は上記1〜3の基準を順に見る必要がある。(2)は「そのセットで失格した者の正解数も含む」という明示的な例外があるため、セット内失格が正解数のカウントを止めない（誤答3回に達しても、そこまでの正解数はそのまま保持する）ことに注意。全ての判定基準が同じ場合は「同率の順位」となる。

## 4. 決定事項

1. **参加者の表示順**: 準決勝の勝ち抜け順（`semifinalRank` 昇順）。新しい座席表は作らない。
2. **20秒のインターバルタイマー**: 実装しない。得点に影響しない運用上の間なので、目視管理に留める。
3. **セコンド（各自2名まで）**: システムには一切持たせない。保存しないその場限りの表示も作らない。
4. **決勝全体の制限時間**: 実装しない。タイマーなしで進行する。
5. **Main画面の見せ方**: 準決勝のような「クイズ中は隠す」区分はしない。正解数・誤答数・獲得セット数を常にリアルタイムで表示する（3rd Roundと同じ）。

以上により、決勝は3rd Round・準決勝と違って**タイマーを一切持たない**、早押しの正誤判定だけのシンプルな進行になる。

## 5. データモデルと採点ロジックの方針（相談中）

### 5.1 スキーマ（Player に追加）

```prisma
// 決勝
finalCorrectCount Int @default(0) // 現在のセットの正解数（セットごとにリセット）
finalWrongCount   Int @default(0) // 現在のセットの誤答数（セットごとにリセット）
finalSetsWon      Int @default(0) // 獲得セット数の累計（リセットしない）
finalRank         Int @default(0) // 最終順位。優勝=1、準優勝=2、第3位=3、未確定=0
```

`finalRank` の1（優勝）はシステムが自動で確定する（5.3節）。2・3（準優勝・第3位）はタイブレークをシステムでは行わず、**Adminが手動で入力する**（5.5節）。

`FinalHistory`（Undo用スナップショット）も他ラウンドと同じ形で追加する。

### 5.2 進行状態（server/FinalHandler.js、DBには持たない）

```js
let finalState = { set: 1 };  // 現在のセット番号。上限なし（先取した瞬間に終了するため）
```

タイマーを持たないため、3rd Round・準決勝の `remainings`/`runningOrder` に相当するものは不要。

### 5.3 採点の自動化レベル（3rd Round の10 up-downと同じ考え方）

「7問正解」「2名がセット内失格」はどちらも同点・判定基準を必要としない一意な決着なので、**正解/誤答ボタンを押した瞬間に自動で確定**させる（3rd Round の10 up-down が10pt到達で即勝ち抜けにするのと同じ）。準決勝の勝ち抜け/失格確定のような「同点ならプレーオフ」という分岐がそもそも無いため、明示的な確定ボタンは不要という理解。

具体的には `applyFinalScore` の中で、正解/誤答を反映した直後に

1. 対象者の `finalCorrectCount >= 7` → そのセットを獲得（`finalSetsWon += 1`）
2. まだセットが決着しておらず、セット内失格（`finalWrongCount >= 3`）が2名に達した → 残る1名がそのセットを獲得（`finalSetsWon += 1`）
3. 1か2でセットを獲得した選手の `finalSetsWon >= 3` になった → その選手が優勝。`finalRank = 1` を自動で付与する。3勝への到達は一意（複数人が同時に3勝目に達することはない）なので、タイブレークは発生しない

を順に判定する。3rd Round の `applyThirdRoundScore` が「Freezeの休み減算→採点→トビ残り判定」と段階を分けているのと同じ構造。

準優勝・第3位（`finalRank` の2・3）はここでは確定しない。5.5節の通り、Adminが別途手動で入力する。

### 5.4 「次のセットへ」は明示操作

セットが決着した後、`finalCorrectCount`・`finalWrongCount` を0に戻して `set` を+1するのは、3rd Round のコース切り替え・準決勝のセット切り替えと同じくスタッフの明示操作にする。自動で次のセットに進めると、決着した瞬間の点数（実況・確認用）が消えてしまうため。

「セットが決着したか」は `finalCorrectCount === 7` または「セット内失格が2名」から都度判定でき、専用の状態は持たない（3rd Round の `finishedOrder` のような「終了処理を走らせたか」の記録が要らない。次のセットへボタンを押すこと自体がリセット処理なので、判定と実行が同じ操作で完結する）。

セットごとの内訳（何セット目に誰が獲得したか）は履歴として残さない。`finalSetsWon`（累計）と、決着した瞬間の `finalCorrectCount`/`finalWrongCount`（最終セットぶんはリセットされずそのまま残る）だけで判定基準(1)(2)は足りるため。

### 5.5 準優勝・第3位はAdminが手動で入力する

> **2026-10-10 変更（ユーザー決定）:** 手動入力はやめ、**優勝者が決定した瞬間に、ルールの判定基準で準優勝・第3位も自動で確定する**。詳細は 6章。以下は経緯として残す。

優勝が決まった時点（`finalRank === 1` の選手が1名決まった時点）で、残り2名について、Admin画面に判定基準の材料（獲得セット数・最終セットの正解数・準決勝での勝ち抜けセット番号）を並べて表示する。Adminはそれを見て、どちらが準優勝かをボタンで選ぶ（選ばれなかった方が自動的に第3位になる。残り2名しかいないため、2択で足りる）。

システムはタイブレークの計算をせず、判定材料の表示までに留める。最終的な順位付けの判断はスタッフが行う。

## 6. 決定事項（2026-10-10、ユーザー回答）— 5.5 より優先

### 6.1 最終順位は優勝決定の瞬間に自動で確定する

優勝者（3セット目を獲得した選手）が決まった時点で、残り2名の順位をルールの判定基準で自動確定する。

1. 獲得セット数が多い順
2. 最終セットでの正解数が多い順（最終セットで失格した選手の正解数も含む）
3. 準決勝での勝ち抜けが早い順（`semifinalRank` が小さい順。準決勝は各セット1名ずつ勝ち抜けるため、ここで必ず決着する）

Admin の手動選択（`setRunnerUp`）は不要になる。

## 7. 見た目（2026-10-15、ユーザー決定・実装）

- Main を黒背景のサイバーパンクのデザインに作り直した（`app/components/Main/MainFinal.tsx`・`FinalCard.tsx`）。見出しは「Final / Triple Seven」、見出し下の線は 1〜4位の順位帯の赤
- 選手カードは画面幅に合わせて横に広げ（3枚）、名前は1行。写真は準決勝で登録したものを中央に置き、左右は同じ写真をぼかして敷く
- 獲得セット数は写真の右側の余白に、ひし形3つ（数字なし・下から点灯）
- 正解数と誤答（× と ・）は 2nd Round と同じくカードの下。正解数はカードのバー（7問で満タン）にも出す
- そのセットで3誤答した選手はグレー（正解数は順位判定に使うので残す）
- 最終順位が決まったら、カードの下に CHAMPION / 2nd / 3rd を出す（優勝者のカードは勝ち抜けと同じオレンジのバー）
- Main・Admin とも、開いた時点で `request_final_sync` を送って進行状態を取り直す
- 準決勝の Admin で第3セットの判定が終わると「Final へ ▶」が出て、モードを決勝に切り替える

## 8. 待機・選手紹介・最終成績（2026-10-17、ユーザー指示・承認済み）

### 8.1 流れ（Admin の1本道ボタン）

| Main 表示（`FinalState.view`） | 内容 | Admin |
